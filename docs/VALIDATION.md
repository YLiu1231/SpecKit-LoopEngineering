## 仍需项目方完成的验证

- 真实项目的完整边界清单、案例分母、有效断言、行为输入范围、环境与数据前提，须在接入时由 Agent 调查并由开发审阅。文件名扫描不能证明语义穷尽，完整运行已有案例也不能证明没有未知错误。
- 四组合校验与恢复例外记录已实现；本轮另实际执行了四种生产/消费版本适配器组合，并用破坏旧字段验证失败检出；具体业务跨系统联调、真实数据兼容、独立回退/联合恢复效果仍须在对应项目执行，不能由本仓夹具替代。
- 原生 Windows 仅验证了设置分支和跨平台语法；PowerShell 安装与 Windows 上的真实项目运行尚未验证。macOS 的已安装命令链已执行。
- 本地确认文件和证据摘要不提供人员身份认证或不可篡改审计。共享报告须随正常 Git 提交同步；运行时不自动提交、推送、合并或发布。
- 自动化只在关键节点读已同步仓库，不提供同步守护进程；当前外部系统状态取决于权威发布源和本地同步可用性。

## 使用入口

先阅读 [增量运行手册](INCREMENTAL-WORKFLOW.md)。在一个现有项目执行 `/loop-init`，完成真实基线和案例目录配置后，按四个 Loop 开始增量。既有 constitution 会保留；若它与新准出规则冲突，需由项目维护者明确处理，安装器不会覆盖已成立的项目约束。

## 本轮独立复核修复

- 本地和共享证据都从原始结果重新计算：逐 runner 精确覆盖、完整目录分母、摘要一致性和退出码。运行中修改目录也使证据失效。
- context 关键节点自动感知相关新交接；回执绑定目标组合，已验证回执绑定消费方特性，历史结果不得泛化。
- 发布记录必须连续单链；收敛交接必须包含被测实现，Git 引用比较包含已删除文件。
- 每个 US 不能因共享 FR 而从映射遗漏；已解决问题必须有当前证据；初始化不能误把特性分支识别为主干。
